# Інформаційна система догляду за міськими зеленими насадженнями

Курсова робота з дисципліни «Кросплатформене програмування», варіант 19.
Студент: Педько Валентин Юрійович, група 202-ТН.

## Що реалізовано
- Сутності: **Дерево**, **Огляд**, **Заявка на роботи**, **Наряд** (повний CRUD).
- Життєвий цикл заявки: СТВОРЕНО → ПЕРЕВІРЕНО → ЗАПЛАНОВАНО → ВИКОНАНО (лише на один крок уперед).
- Інтегральний показник `I = 0,40·F1 + 0,35·F2 + 0,25·F3`, фактори нормуються до 0–100:
  - `F1 = 100 − health_score` (технічний стан з огляду);
  - `F2 = min(100, пішоходів за годину ÷ 500 × 100)` (інтенсивність перебування людей);
  - `F3 = (30 − строк у добах) ÷ 30 × 100`, обмежено 0…100 (терміновість).
- Фоновий CSV-імпорт реєстру дерев через JavaFX `Task` із `ProgressBar` та скасуванням.
- Валідація (клієнт і сервер), обробка помилок, логування, 29 тестів JUnit 5.

## Архітектура
`JavaFX → ApiClient → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL`

```
server/   Maven, WAR для Tomcat 9.x (Servlet API, Service, DAO, MySQL)
client/   Maven, JavaFX-клієнт; client/sample-data/ — демонстраційні CSV
database.sql   створення БД urban_green і демонстраційних даних
```

## Вимоги
JDK 21, Maven 3.9+, MySQL 8.x, Apache Tomcat **9.x** (простір імен `javax.servlet`).

## Запуск
1. **База даних** (видаляє й створює `urban_green` заново):
   ```
   mysql -u root -p < database.sql
   ```
2. **Змінні середовища** сервера (задайте до запуску Tomcat у тому ж терміналі):
   | Змінна | За замовчуванням |
   |---|---|
   | `GREEN_DB_URL` | `jdbc:mysql://localhost:3306/urban_green?...` |
   | `GREEN_DB_USER` | `root` |
   | `GREEN_DB_PASSWORD` | порожній |
3. **Сервер**:
   ```
   cd server
   mvn clean package
   ```
   Скопіюйте `target/green-server.war` до `webapps` Tomcat 9 і запустіть Tomcat.
   Перевірка: `http://localhost:8080/green-server/trees` повертає JSON.
4. **Клієнт**:
   ```
   cd client
   mvn javafx:run
   ```
   Іншу адресу сервера задає змінна `GREEN_API_URL` (за замовчуванням `http://localhost:8080/green-server`).
5. **Тести** (не потребують MySQL і Tomcat): `mvn test` у `server/` та `client/`.

## HTTP-інтерфейс
| Запит | Дія |
|---|---|
| `GET /trees`, `/inspections`, `/requests`, `/assignments` | список |
| `POST` на ті самі адреси (JSON у тілі) | створення, код 201 |
| `PUT` на ті самі адреси (JSON у тілі) | редагування |
| `DELETE ...?id=N` | видалення |
| `PUT /requests?action=transition&id=N&state=VERIFIED` | зміна стану заявки |

Помилки даних повертаються з кодом 400 і полем `error`, технічні збої — з кодом 500.

## CSV-імпорт
Кодування UTF-8, роздільник `;`, обов'язковий заголовок:
```
code;species;location;planting_year;pedestrians_per_hour
```
- `client/sample-data/trees.csv` — 6 коректних рядків;
- `client/sample-data/trees_with_errors.csv` — 5 рядків, з них 3 помилкові (нечисловий рік, неповний рядок, дублікат коду).

Помилка в одному рядку не зупиняє імпорт: рядок рахується як помилковий, решта обробляється.

## Контрольний сценарій
Створити дерево → додати огляд → створити заявку (стан СТВОРЕНО, F1–F3 та I розраховано автоматично) →
перевести за станами до ВИКОНАНО → спробувати перехід СТВОРЕНО → ВИКОНАНО (повідомлення про помилку) →
призначити наряд → імпортувати обидва CSV → видалити дерево (пов'язані записи видаляються каскадно).
